### Summary

Solid fix for two real production bugs: (1) passenger count not persisting when returning to search from Trip Summary (#949), and (2) the "change return trip" button incorrectly navigating to depart results and clearing the return date. Applies the same `dispatch(searchActions.setDirection(direction))` pattern established in PR #933 for the add-return-trip button.

The implementation is sound. `buildSearchUrl`'s `passengers: seats` addition correctly handles `undefined` seats (qs.stringify omits the param cleanly), and the `departDateTimestamp`/`returnDateTimestamp` removal from the `getSearchBannerState` call is safe — they were excess positional arguments silently ignored by JS. Tests cover the core behavior well.

Prior review by bsaltersheridan2 has two open findings (mobile back-arrow stale-direction bug, clamped seats question) — both remain open and valid.

`packages/wanderu-components-search/src/components/SearchBanner/BannerCardList/BannerCardList.jsx`

`BannerCard.propTypes` was updated with `onNavigate: PropTypes.func` (good), but `BannerCardList.propTypes`'s shape for `complete` array items was not.

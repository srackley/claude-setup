### Disputed (1)

**`carriers.js:35-45` — Missing `/ tripSeats` normalization for stale multi-pax totals**  
`paxAwarePricing` multiplies `trip.pricing` directly by `requestedSeats` when `tripSeats !== requestedSeats`. For a stale 2-pax Amtrak trip (`trip.seats='2'`, `trip.pricing=$200`) in a 3-pax search, this produces `$200 × 3 = $600` instead of `($200/2) × 3 = $300`. The canonical `selectTripPrices` in `wanderu-ducks-trips/selectors.js:301-360` handles this with `normalizedSeats = tripSeats > 1 ? tripSeats : 1`. The stale scenario is confirmed reachable: `serializeSearchParams` excludes `seats` from the search key. Challenger weakened to DISPUTED — exposure is transient (sidebar only, until next JIT scrape completes, not a booking-path bug).

### Nits (1)

**`carriers.js:60` + comment `19-27` — NaN path undocumented, diverges from M1**  
`Number.parseInt(trip.seats, 10)` returns `NaN` when `trip.seats` is absent. `NaN === seats` is always false, so multiply always fires — correct behavior, but undocumented. M1's equivalent at `wanderu-ducks-trips/selectors.js:298-302` has an explicit comment. A future maintainer adding `if (!isNaN(tripSeats))` would silently break single-pax cached trip handling. Challenger: Confirmed.

- `selectTravelerInfo` throw: pre-existing pattern throughout `tripSummary/selectors.js`
- `multiplyPriceObj` NaN on non-numeric values: theoretical
- Cross-package import: same-package boundary, not a violation

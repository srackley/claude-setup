### What the PR Does

Fixes Amplitude SDK cookie scoping: the cookie was set on the app's serving hostname instead of the shared parent domain, breaking device ID continuity across apps (ui-react, canopy, nexus, experiment-router). Fix: pass `cookieOptions: { domain: appSettings?.config?.amplitude?.cookieDomain }` to `amplitude.init()`, with `cookieDomain` sourced from per-env YAML config. Also bumps `@amplitude/analytics-browser` from `^2.22.0` to `^2.38.1` (resolves to 2.42.3). The implementation change is correct and minimal.

---

### SUGGESTIONS (1)

**packages/wanderu-analytics/src/tests/AmplitudeProvider.test.tsx:843-872**

The new `'AmplitudeProvider cookieOptions.domain'` test confirms the SDK receives a `cookieOptions.domain` key, but never injects a real `cookieDomain` value into the mock config. Because `ssrHydratedState()` provides no `amplitude.cookieDomain`, the test asserts the `domain` key exists with value `undefined` — which means it cannot verify the value actually flows from config to the SDK. The `setConfig` helper exported by `__mocks__/wanderu-config.js` supports setting a real value; using it to inject `.wanderu.com` and asserting `toBe('.wanderu.com')` would verify the actual end-to-end data flow and catch regressions where the value is silently swallowed.

Suggested addition:
```typescript
it('forwards cookieDomain config value to cookieOptions.domain', async () => {
    const original = appSettings.config.amplitude.cookieDomain;
    appSettings.config.amplitude.cookieDomain = '.wanderu.com';
    try {
        const store = createStore(ssrHydratedState());
        render(<Provider store={store}><AmplitudeProvider>{null}</AmplitudeProvider></Provider>);
        await flushEffects();
        const initOptions = mockedInit.mock.calls[0][1] as { cookieOptions?: { domain?: string } };
        expect(initOptions.cookieOptions?.domain).toBe('.wanderu.com');
    } finally {
        appSettings.config.amplitude.cookieDomain = original;
    }
});
```

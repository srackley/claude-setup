## [ui-react#896] fix: per-env Amplitude cookieDomain via cookieOptions.domain

**URL:** https://github.com/wanderu/ui-react/pull/896
**Classification:** NEEDS_REVIEW
**Reviewed:** 2026-05-25
**Branch:** feat/amplitude-cookie-domain-873 @ 081d9ed1

### Summary

Fixes Amplitude cookie domain scoping for cross-app device ID continuity. Previously, `amplitude.init()` in the browser SDK defaulted to scoping cookies to the serving hostname, breaking device ID sharing across canopy, nexus, ui-react, and experiment-router. The PR adds `cookieDomain` to per-env config (`.wanderu.dev` for dev, `.wanderu.com` for prod), then passes it to the SDK as `cookieOptions: { domain: appSettings?.config?.amplitude?.cookieDomain }`. Closes #873.

**Files changed:** 6 — `.config/dev.yaml`, `.config/prod.yaml`, `package.json`, `AmplitudeProvider.tsx`, `AmplitudeProvider.test.tsx`, `yarn.lock`. Also bumps `@amplitude/analytics-browser` from `^2.22.0` → `^2.38.1` (resolves to 2.42.3).

### Agent Findings

All 5 agents ran (code-reviewer, silent-failure-hunter, type-design-analyzer, pr-test-analyzer, comment-analyzer). 3 findings classified as valid after deduplication, false-positive elimination, verification, and independent challenge.

### Verdict

**Blocking (1):**

`packages/wanderu-analytics/src/utils.ts:461` — Server-side cookie domain still hardcoded to `.wanderu.com` while PR scopes browser SDK to per-env config. `handleAmplitudeCookies` sets the SSR device-ID seed cookie with `domain: '.wanderu.com'` hardcoded (the comment there even reads "this should be the same domain used by the Amplitude JS SDK"). In dev, the browser SDK will scope cookies to `.wanderu.dev` (from `dev.yaml: cookieDomain: .wanderu.dev`) while the server seeds to `.wanderu.com`. Dev has `amplitude.apiKey` set so `handleAmplitudeCookies` runs there. The domain mismatch means SSR-seeded device IDs are invisible to the browser SDK in dev, breaking the cross-subdomain continuity this PR exists to fix. **Fix:** `domain: appSettings?.config?.amplitude?.cookieDomain ?? '.wanderu.com'` — `appSettings` is already in scope on line 439.

**Suggestions (1):**

`packages/wanderu-analytics/src/tests/AmplitudeProvider.test.tsx:862-870` — New test verifies `cookieOptions.domain` key exists but not its value. The test fixture has no `cookieDomain` in appconfig so `domain` is `undefined`; `toHaveProperty('domain')` passes vacuously. An implementation that always passed `cookieOptions: { domain: undefined }` regardless of config would pass this test. **Fix:** Add a test with `cookieDomain: '.wanderu.com'` mocked into config and assert `expect(initOptions.cookieOptions?.domain).toBe('.wanderu.com')`.

**Nits:** none

**Disputed (1, not posted):** New describe block's `beforeEach` missing resets present in other blocks — weakened by challenger (module-level mock factory mitigates isolation risk; consistency note only).

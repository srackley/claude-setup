### DISPUTED FINDINGS
*Weakened by independent challengers. Not posted — shown for awareness.*

**DISPUTED-1: `SnowplowIdsPlugin.execute()` has no try/catch**  
`packages/wanderu-analytics/src/AmplitudeProvider.tsx` lines 55–80  
The `execute()` enrichment method calls `SnowplowService.getDomainUserInfo()` without any try/catch. In SSR or never-bootstrapped-Snowplow environments, `_getSnowplow()` returns `undefined` and `undefined(callback)` throws a TypeError that propagates uncaught out of Amplitude's enrichment pipeline, potentially dropping the event. **Weakened:** the typical client-side path is safe (queuing stub installed by `_setupWindow()`). Narrow SSR risk remains. Adding `try/catch` with `return event` fallback in `execute()` would eliminate it.

**DISPUTED-2: `exposureTrackingProvider.track` callback not directly tested**  
`packages/wanderu-analytics/src/AmplitudeProvider.tsx` lines 167–176  
The custom `exposureTrackingProvider` (the primary fix) has no test asserting `amplitude.track('$exposure', exposure)` is called. `amplitude.track` is not mocked in `AmplitudeProvider.test.tsx`. **Weakened:** `experiment.exposure(flagName)` call sites are tested in `hooks.test.tsx`. The untested gap is specifically the callback wiring. Easy to add: capture config arg to `mockInitializeWithAmplitudeAnalytics`, call `config.exposureTrackingProvider.track(mockExposure)`, assert `mockAmplitudeTrack` was called.

**DISPUTED-3: Comment says "Module-level ref" for a plain `let`**  
`packages/wanderu-analytics/src/AmplitudeProvider.tsx` line 83  
"ref" should be "variable" or "singleton" — the codebase uses `Ref` suffix for actual React refs (`useRef`). **Weakened:** "Module-level" prefix already clarifies scope; confusion window is near-zero. Marginal nit.

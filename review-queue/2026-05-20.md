### Findings

#### SUGGESTION (1)

**TicketLookupForm.test.tsx:~248 — Catch-path test doesn't verify the terminal `.error()` call**

The "shows inline error when findBooking throws unexpectedly" test asserts `mockWithMetadata` was called with `{ outcome: 'server_error' }`. But the catch block calls `.withError(error).withMetadata({ outcome: 'server_error' }).error('Ticket lookup failed unexpectedly')`, and the terminal `.error(...)` fires on an anonymous untracked `vi.fn()` from `beforeEach`'s `mockReturnValue`. If the `.error()` call were removed or the message changed, all tests would still pass.

Fix: add `const mockError = vi.fn()` at module scope, include it in `mockWithMetadata.mockReturnValue({ error: mockError, info: mockInfo })` in `beforeEach`, then assert `expect(mockError).toHaveBeenCalled()` in the catch-path test.

#### NITS (2)

**TicketLookupForm.test.tsx:25 — `chained.info = vi.fn()` is dead code**

Every `.info()` call in the component chains off `.withMetadata(...)`, which returns `{ info: mockInfo }` from `beforeEach`. `chained.info` is never reached and can be removed.

**TicketLookupForm.tsx:22 — LOGGER_CONTEXT comment ambiguous on causal chain**

> "an inline literal would re-fire effects depending on `logger`"

The actual chain is: new `context` reference → `useMemo([logger, context])` recomputes → new `Logger` instance → `useEffect([logger, result])` re-fires. The word `logger` is ambiguous between the `useObservability` logger and the `useLogger` return value.

Suggested: _"An inline literal creates a new object each render, causing useLogger's useMemo to return a new Logger instance and re-fire effects on [logger]."_

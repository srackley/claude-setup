### Confirmed Findings (Blocking)

**[.deploy/helm-chart/templates/grafana-monitors.yaml:356] — BLOCKING**  
The blog-errors alert uses `|~ "(?i)status.{1,4}5[0-9][0-9]"` to detect 5xx responses from nginx. The nginx `log_format main` (nginx-conf.yaml lines 22-25) emits the HTTP status as a bare space-separated integer — `$status` → `502` — with no preceding text "status". The regex requires the literal word "status" before the 5xx number and matches zero real log lines. The alert is permanently broken and will never fire.

Fix: replace with `|~ "\" 5[0-9][0-9] "` (status code immediately follows the closing quote of `$request` in nginx access log format).

**[.deploy/helm-chart/templates/grafana-monitors.yaml:283,357] — BLOCKING**  
`queryType: instant` is indented at 12 spaces (inside `model:`) in both Loki data items. The Grafana Alerting data-item schema requires `queryType` at 10-space indent as a sibling of `model:`. The alerting engine routes query type before passing the model blob to the datasource plugin; `queryType` inside `model:` is not read and the queries run in range mode, returning a time-series matrix instead of a scalar — causing the threshold expression to evaluate against the wrong value or produce a type-mismatch error.

Fix: move `queryType: instant` to 10-space indent (sibling of `model:`) in both Loki data items. (The Prometheus `instant: true` inside `model:` is a Prometheus-plugin-specific convention, not evidence this is valid for Loki.)
